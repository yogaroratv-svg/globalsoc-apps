Six Old PHP-Stack RCEs That Still Arrive Every Day, With the Payloads

In 24 days a PHP honeypot received 557 requests for six remote code execution bugs disclosed between 2012 and 2024. Here is each one as it arrived: the request, the payload, what it would do on a vulnerable server, and why it failed on this one.

Key Sections: Summary · PHPUnit eval-stdin · A Dropper Without a Check · PHP-CGI · ThinkPHP 5 · pearcmd · Apache Traversal · Laravel Ignition · Did Anything Work? · Packet Capture Note · IOCs · Detection (KQL) · Mitigation

Part of the PHP honeypot series. Data: nginx request log and Apache container log from vm-php-cve-lab, 22 October – 15 November 2026 (UTC). URLs are defanged. Nothing on this page was executed.

2. PHPUnit eval-stdin.php (CVE-2017-9841)

PHPUnit before 4.8.28 / 5.6.3 shipped src/Util/PHP/eval-stdin.php, a helper containing eval('?>' . file_get_contents('php://input'));. If vendor/ is inside the web root, anyone can POST PHP code to that file and have it run. It is a test tool that should never be deployed, which is why it is still found nine years on.

4. PHP-CGI Argument Injection (CVE-2012-1823, CVE-2024-4577)

When PHP runs as a CGI binary, a query string with no = is passed to it as command-line arguments. ?-d+allow_url_include=1+-d+auto_prepend_file=php://input makes PHP execute the POST body. The 2012 fix rejected a leading hyphen; in 2024 it was found that Windows "best fit" code page conversion turns the soft hyphen 0xAD into a hyphen after that check has run.

All 59 requests of this type came from the RedTail bot, five per run. The request lines, the 1,189-byte payload that carries its own SSH key, and its decoding are in the RedTail post.

5. ThinkPHP 5 invokefunction (CVE-2018-20062)

ThinkPHP 5.0.x before 5.0.23 and 5.1.x before 5.1.31 did not validate the controller name in the s routing parameter. s=/index/\think\app/invokefunction reaches the framework's own App::invokeFunction, and the remaining parameters name any PHP function and its arguments.

6. pearcmd.php Through a File Include

This is a technique, not a CVE. The official PHP Docker images ship PEAR at /usr/local/lib/php/pearcmd.php and have register_argc_argv on. If an application has a local file inclusion bug, the attacker includes pearcmd.php; PEAR then reads the query string as its command line. config-create writes a config file to a path the attacker chooses, with attacker-controlled content, which gives a PHP file on disk. A second request includes it.

11 requests from 11 IPs, all RedTail. The pair:

2026-10-23 14:21:27 UTC  169.58.137.184 (France)  status 200  request 257 bytes  response 3689 bytes

GET /index.php?lang=../../../../../../../../usr/local/lib/php/pearcmd&+config-create+/&/<?echo(md5("hi")) ?>+/tmp/index1.php HTTP/1.1
User-Agent: libredtail-http

GET /index.php?lang=../../../../../../../../tmp/index1 HTTP/1.1

The first request asks PEAR to write /tmp/index1.php containing <?echo(md5("hi"));?>. The second includes /tmp/index1 (the application is expected to add .php) and looks for the hash. The guess is that the site has a lang parameter that is passed to include.

The honeypot is exactly the Docker image this targets, and pearcmd.php is where the bot expects it. What is missing is the include: index.php ignores lang. No /tmp/index1.php was created (the container's filesystem diff is in the RedTail post).

7. Apache Path Traversal to /bin/sh (CVE-2021-41773, CVE-2021-42013)

Apache 2.4.49 failed to normalise .%2e, and 2.4.50's fix missed the double-encoded form. With mod_cgi enabled, a POST to /cgi-bin/<traversal>/bin/sh runs the request body as a shell script.

29 requests from 16 IPs, in two forms:

  16  POST /cgi-bin/.%2e/.%2e/.%2e/.%2e/.%2e/.%2e/.%2e/.%2e/.%2e/.%2e/bin/sh HTTP/1.1
  13  POST /cgi-bin/%%32%65%%32%65/%%32%65%%32%65/%%32%65%%32%65/%%32%65%%32%65/%%32%65%%32%65/%%32%65%%32%65/%%32%65%%32%65/bin/sh HTTP/1.1

We cannot show the payload. nginx sits in front of Apache, treats these paths as invalid, and answers 400 without reading the body. Nothing was forwarded: there is no matching line in the Apache container log. Twelve of the 16 source IPs are the RedTail scanners, which open every run with this pair; the other four sent only these requests and nothing else. For the RedTail runs the body was very likely the same dropper with a different campaign tag, but that is inference.

This is the one case in the series where the reverse proxy removed evidence. A capture of raw port 80 traffic would have had the body; see section 10.

8. Laravel Ignition (CVE-2021-3129)

Ignition before 2.5.2, the error page in Laravel's debug mode, exposes /_ignition/execute-solution. The MakeViewVariableOptionalSolution class passes a viewFile parameter to file_get_contents and file_put_contents. With php://filter chains an attacker rewrites storage/logs/laravel.log into a PHAR archive and then loads it with phar://, which deserialises an object and runs code.

10. Packet Capture Note

The lab ran a rolling packet capture (tcpdump, full snap length, 20 files of 10 MB) on port 80 and the Docker bridges. A ring that small holds about a day and a half of traffic, and the last of it was overwritten on 15 November when the VM was restarted and a large package download passed through the capture filter. The packets for the requests in this post no longer exist. What remains is the nginx request log (request line, User-Agent, Content-Type and the complete request body) and the Apache log from inside the container, both shipped to Microsoft Sentinel as they were written. Every payload on this page is from those two sources.

12. Detection (KQL)

All six in one query against the honeypot's nginx log in Sentinel:

Syslog
| where TimeGenerated > ago(7d)
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| extend Client = tostring(j.client), Request = tostring(j.request), Body = tostring(j.body), Status = toint(j.status)
| extend Technique = case(
    Request has "eval-stdin.php", "PHPUnit CVE-2017-9841",
    Request has_any ("auto_prepend_file", "allow_url_include"), "PHP-CGI CVE-2012-1823/CVE-2024-4577",
    Request has "invokefunction" and Request has "think", "ThinkPHP 5 RCE",
    Request has "pearcmd", "pearcmd via LFI",
    Request has "/cgi-bin/" and Request has_any (".%2e", "%%32%65", "%252e"), "Apache CVE-2021-41773/42013",
    Request has "_ignition/", "Laravel Ignition CVE-2021-3129",
    "")
| where isnotempty(Technique)
| summarize Requests = count(), Non404 = countif(Status !in (400, 404)), Sample = take_any(Request) by Client, Technique
| order by Non404 desc, Requests desc

The column that matters on a real estate is Non404. A 200 on eval-stdin.php or /_ignition/execute-solution means the file exists and should be treated as an incident until shown otherwise. For web servers that log response size, a second useful signal is an exploit request whose response size differs from the same URL without the exploit parameters.

13. Mitigation

  • PHPUnit: deploy with composer install --no-dev; keep vendor/ outside the web root or deny it at the web server. Search web roots for eval-stdin.php.
  • PHP-CGI: use PHP-FPM or mod_php. On Windows/XAMPP, update PHP to 8.3.8 / 8.2.20 / 8.1.29 or later.
  • ThinkPHP: 5.0.24 / 5.1.31 or later; most affected sites are abandoned and should be retired.
  • pearcmd: remove PEAR from production images (rm -rf /usr/local/lib/php/pearcmd.php or a multi-stage build) and set register_argc_argv=Off. Fix the include bug that makes it reachable.
  • Apache: nothing later than 2.4.50 is affected. A reverse proxy that rejects malformed paths, as nginx did here, blocks this class outright.
  • Laravel: APP_DEBUG=false in production; Ignition 2.5.2 or later.
  • Egress: every dropper in this post needs the web server to open an outbound connection. Default-deny outbound from the web tier turns a successful exploit into a failed download.
