Who Found Our Honeypot First? A Census of 24 Named Internet Scanners

The first stranger reached our new honeypot 33 minutes after it started. Within a day 86 addresses had visited. We list every scanner that named itself in its User-Agent (Censys, Palo Alto Xpanse, Infrawatch, Nokia, Odin, universities and more), when each arrived, what it asked for, and which "research" scanners went straight for .env files.

Key Sections: Summary · The First Day · Named Scanners · What They Ask For · Names That Claim Research · Tools, Not Organisations · Should You Block Them? · Detection (KQL)

Part of the PHP honeypot series. Data: nginx request log from vm-php-cve-lab, 22 October – 15 November 2026 (UTC; the VM was switched off from 9 to 15 November). Scanner names are as the scanners gave them; we did not verify ownership of the addresses.

1. Summary

  • The vulnerable container started at 2026-10-22 05:01:27 UTC. The first request from the internet arrived 33 minutes later.
  • In the first hour 2 addresses sent 3 requests. In the first 24 hours, 86 addresses sent 666.
  • 24 scanners named themselves in their User-Agent, usually with a link that explains the scan. Together they sent 831 requests from 417 addresses: 7.9% of the 10,509 external requests. Everything else came from clients that did not say who they were.
  • Several clients call themselves "research" or "authorized" and then request .env, .git and cloud credential files. A name in a User-Agent is a claim, not an identity.

/mcp, /api/mcp and /sse are where Model Context Protocol servers listen. An exposed MCP server can give anyone the tools it gives an AI agent, which is why internet indexes now look for them. The AI post covers who else asks.

Palo Alto Networks Cortex Xpanse asked almost only for /, plus security.txt and once a path that cannot exist (/yawhpsiabsent), the same "is everything a 200?" check described in the spray scanner post. Xpanse is sold to organisations to find their own internet-facing assets, so the data ends up with defenders.

The useful test is not the name but the behaviour: does the client link to a page that names an organisation and offers an opt-out, and does it only read public pages? Censys, Xpanse, Infrawatch, Odin, Modat and the university scanners pass. The clients in this table do not.

6. Tools, Not Organisations

Some User-Agents name software that anyone can run:

  • zgrab, the scanner behind several research projects and many private ones: 114 requests from 91 addresses. Most just fetched /; others asked for SAP NetWeaver's /developmentserver/metadatauploader (the CVE-2025-31324 upload endpoint), Apache Druid's console and Red Lion industrial devices. The tool tells you nothing about who ran it: / (55), /developmentserver/metadatauploader (18), /druid/index.html (6), /portal/redlion (6), /actuator/health (6).
  • IVRE with masscan, an open-source network recon framework.
  • mrtscan/1.0, which names a cloud region (westus) and nothing else.

7. Should You Block Them?

Blocking the named scanners keeps your servers out of public indexes, and attackers do use those indexes to pick targets. But the named scanners were 8% of external traffic here, and blocking them does nothing about the other 92%, which found the server just as fast without them. Meanwhile the same indexes are how defenders and their providers (attack-surface tools like Xpanse, threat-intelligence feeds, CERT notification services) find exposures and tell you about them.

Our recommendation: do not rely on hiding. Assume everything you expose is in every index within a day, because here it was. If you want to opt out, use the scanners' published opt-out pages rather than IP blocklists, which go stale. And treat clients that claim to be research but fetch secrets as what they are.

8. Detection (KQL)

Tag self-identified scanners so they can be filtered or reviewed separately, and flag "research" names that request sensitive paths:

let Known = dynamic(["CensysInspect", "Infrawatch", "Palo Alto Networks", "Expanse", "GenomeCrawler", "ForestEngine", "ModatScanner", "Odin", "InternetMeasurement", "NetcraftSurveyAgent"]);
Syslog
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| extend Client = tostring(j.client), UA = tostring(j.user_agent), Uri = tostring(j.uri)
| extend Named = UA has_any (Known)
| extend ClaimsResearch = UA matches regex @"(?i)research|authori[sz]ed|scanner|scan/"
| extend Sensitive = Uri matches regex @"(?i)/\.env|/\.git/|credentials|\.aws/|terraform\.tfvars|backup\.(zip|tar)|wp-config"
| summarize Requests = count(), SensitiveHits = countif(Sensitive), Paths = make_set(Uri, 15) by Client, UA, Named, ClaimsResearch
| where (ClaimsResearch and not(Named) and SensitiveHits > 0) or (Named and SensitiveHits > 0)
| order by SensitiveHits desc
