131,113 SSH Brute-Force Attempts in 18 Days — and Why Our Password Logger Captured Zero Passwords

Port 22 on our PHP honeypot took 131,113 password guesses from 1,227 IPs using 3,181 usernames. The PAM password logger recorded none of the real passwords — only OpenSSH's decoy string — but that decoy still leaked the length of every guess.

Key Sections: The Numbers · Usernames Tried · The Logger That Caught Nothing · Password Lengths · Who Was Guessing · Packet Capture Note · Detection (KQL) · Mitigation

Part of the PHP honeypot series. Data: /var/log/auth.log and the PAM logger output on vm-php-cve-lab, 22 October – 15 November 2026 (UTC; the VM was switched off from 9 to 15 November).

3. The Logger That Caught Nothing

The lab had a PAM hook (log-ssh-password.py, run through pam_exec with expose_authtok) meant to record every password tried. After 131,113 attempts it had recorded 46 distinct "passwords". All of them look like this:

RawHex: 080a0d7f494e43 | Str: '\x08\n\r\x7fINC'                         x 8,916
RawHex: 080a0d7f494e434f5252 | Str: '\x08\n\r\x7fINCORR'                x 8,905
RawHex: 080a0d | Str: '\x08\n\r'                                        x 6,975

RawHex: 08 | Str: '\x08'                                                x 4,051
RawHex: 080a0d7f494e434f52524543 | Str: '\x08\n\r\x7fINCORREC'          x 3,766
RawHex: 080a0d7f494e434f5252454354 | Str: '\x08\n\r\x7fINCORRECT'       x 1,653

That is not attacker input. It is OpenSSH protecting itself. When a login is for a user that does not exist, or for root when root password login is disabled, sshd does not hand the real password to PAM. It substitutes a decoy built from the constant \b\n\r\177INCORRECT (backspace, newline, carriage return, DEL, then the word INCORRECT), so that PAM takes the same time as it would for a real user and the attacker cannot tell valid usernames from invalid ones by timing. The code is fake_password() in OpenSSH's auth-pam.c.

Every username the attackers tried was either non-existent on the VM or root, so every single password the hook saw was the decoy.

Lesson: a pam_exec password logger on a stock OpenSSH server only sees real passwords for accounts that exist and are allowed to log in with a password. To collect attacker passwords you need a purpose-built SSH honeypot (Cowrie or similar), or decoy accounts that really exist.

4. What the Decoy Still Leaked: Password Lengths

fake_password() repeats the decoy string until it is exactly as long as the password the client sent. So although the content is gone, the length of every guess is preserved. A logged value of \x08\n\r\x7fINCO (8 bytes) means the attacker's password was 8 characters long.

Length distribution over 131,113 logged attempts:

The most common lengths were 8 chars (27,281), 6 chars (23,041), 9 chars (14,354), 4 chars (12,787). Short guesses dominate: this is dictionary traffic (123456, password, admin123-style lists), not targeted credential stuffing with long leaked passwords.

6. Packet Capture Note

The honeypot's tcpdump service captured port 80 and the Docker bridges only, so there are no SSH packets to analyse; SSH is encrypted after the key exchange in any case. Everything in this post comes from sshd log lines and the PAM hook output.

7. Detection (KQL)

Brute-force sources by volume and username spread, from the Sentinel Syslog table:

Syslog
| where TimeGenerated > ago(1d)
| where Facility in ("auth", "authpriv") and ProcessName == "sshd"
| where SyslogMessage has_any ("Failed password", "Invalid user")
| extend SrcIp = extract(@"from (\d+\.\d+\.\d+\.\d+)", 1, SyslogMessage),
         User  = extract(@"(?:for invalid user|Invalid user|for) (\S+)", 1, SyslogMessage)
| summarize Attempts = count(), Users = dcount(User), Sample = make_set(User, 10) by SrcIp, Computer
| where Attempts >= 20 or Users >= 5
| order by Attempts desc

Any successful password login after failures from the same address:

let failed = Syslog
| where TimeGenerated > ago(1d) and ProcessName == "sshd" and SyslogMessage has "Failed password"
| extend SrcIp = extract(@"from (\d+\.\d+\.\d+\.\d+)", 1, SyslogMessage)
| summarize Failures = count() by SrcIp;
Syslog
| where TimeGenerated > ago(1d) and ProcessName == "sshd" and SyslogMessage has "Accepted password"
| extend SrcIp = extract(@"from (\d+\.\d+\.\d+\.\d+)", 1, SyslogMessage)
| join kind=inner failed on SrcIp
| project TimeGenerated, Computer, SrcIp, Failures, SyslogMessage

8. Mitigation

  • Set PasswordAuthentication no and use keys. Every one of the 131,113 attempts fails at this step.
  • Do not expose port 22 to the internet. Use Azure Bastion, a VPN, or an NSG rule limited to your own addresses.
  • Do not create accounts named after the software they run (claude, deploy, minecraft, jenkins). If you must, they get no password and no shell.
  • Keep PermitRootLogin prohibit-password (the Ubuntu default) or no.
