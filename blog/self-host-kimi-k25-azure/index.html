Feasibility decision

Verdict: feasible, with one change of hardware and no change of model. Run moonshotai/Kimi-K2.5 (native INT4) on one Standard_ND96isr_H200_v5 (8× H200 141 GB) with vLLM, TP=8. vLLM's recipe for Kimi K2.5 documents exactly this setup [DOC]. The two configurations you named are not suitable: 8× A100-80GB and 8× H100-80GB cannot hold the K2.5 weights plus working memory [CALC], and the NVFP4 variant needs Blackwell GPUs, which Azure only offers as rack-scale GB200 VMs [DOC]. The latest open-weight Kimi, K3, is not feasible on your budget: its smallest documented deployment is 32× H200 [DOC].

At list price, $5,000 USD of credit buys about 45 billed GPU-hours (roughly 30–37 hours of actual use) of the recommended VM, not 180 (Section 6). If your credit is that tight, a pay-per-token Kimi endpoint in Azure AI Foundry may serve you better. That would not be self-hosted; see the last row of the table below.

Storage, download and startup [CALC]

  • The weights need ≥ 600 GB of storage, plus about 25 GB for the container image.

  • A managed disk is capped by the VM's uncached throughput of 612 MBps (ND H200 v5 spec). Reading 595 GB from it takes at least about 16 minutes on every cold start. A P30 disk (200 MBps) would take about 50 minutes.

  • The plan therefore keeps the durable copy in Blob storage (about $11/month) and restores it to the VM's local NVMe (8 disks, 28 TiB, ephemeral) at each start with azcopy. Restore time is unknown until measured [EXP]. The VM has 80 Gbps of network bandwidth, but Blob throughput is the limit.

  • The first download from Hugging Face is a one-time cost. Inbound data transfer is free [DOC: price API, "Standard Data Transfer In 0.0"].

Gates before any spend

  1. [SUB] Standard NDSH200v5 Family vCPUs quota of at least 96 in the chosen region. A new subscription usually has 0 and must file a quota request.

  2. [SUB] The SKU is unrestricted for your subscription in that region (az vm list-skus, Section 1).

  3. [SUB] Your credit type covers ND-series compute. Some sponsorship and free credits exclude GPU or Marketplace items; check Cost Management.

  4. [EXP] A real allocation succeeds. Approved quota does not guarantee physical capacity.

If gate 1 or 4 fails in every US region, fall back to Standard_ND96isr_MI300X_v5, which runs the same model through vLLM ROCm per the recipe, or stop.

Target architecture

You choose one edge path: nginx on the VM (A) or Cloudflare's edge plus cloudflared (B). Both converge on vLLM, which listens only on loopback; Open WebUI talks to it on the private Docker network. Weights come from Blob storage to local NVMe at each boot, and two independent mechanisms can deallocate the VM.

1. Azure infrastructure provisioning

This section builds one GPU VM in a private-by-default subnet. It has a Standard public IP used for outbound traffic (Hugging Face, apt, Cloudflare) and no inbound internet rule except the ones a chosen access option adds. A public IP costs $0.005/h; a NAT Gateway would also charge per GB processed on the 595 GB download. Weights live in a Blob container that only the VM's managed identity can reach. Billing starts at az vm create, so run nothing past step 1.5 until gates 1–3 pass.

1.10 Discover local storage before touching it — [VM]

lsblk -d -o NAME,SIZE,MODEL,TYPE,MOUNTPOINTS
lsblk -f
findmnt -t ext4,xfs -o TARGET,SOURCE,SIZE
sudo blkid
cat /proc/mdstat

Illustrative expected output (shape only): one OS disk of about 256G with partitions mounted at /; one temp disk of about 1T, often already mounted at /mnt; and eight nvme*n1 devices of about 3.5T each, model text resembling "Microsoft NVMe Direct Disk". Device names and the image's own NVMe handling vary [EXP].

Apply these rules before any format:

  1. If findmnt shows the NVMe devices already assembled and mounted by the image (for example a RAID under /mnt/nvme), use that mount and skip to 1.11.

  2. Otherwise, select only devices that are type disk, report the NVMe Direct Disk model, are not the OS disk, have no partitions, no filesystem signature (sudo wipefs -n /dev/X prints nothing), and are not in /proc/mdstat.

  3. Never format the OS disk or any device with existing data.

# [VM] Build the candidate list from evidence, then STOP and read it before continuing.
CAND=$(lsblk -dn -o NAME,TYPE,MODEL | awk '$2=="disk" && /NVMe Direct/ {print "/dev/"$1}')
for d in $CAND; do
  echo "$d parts=$(lsblk -n "$d" | wc -l) sig=$(sudo wipefs -n "$d" | wc -l)"
done

Proceed only if every listed device shows parts=1 (the disk itself) and sig=0. Then:

# [VM] local-nvme.sh — also reused at every boot (Section 6), because NVMe is wiped on deallocate
set -euo pipefail
N=$(echo $CAND | wc -w)
sudo mdadm --create /dev/md/kimi --level=0 --raid-devices="$N" $CAND --force --run
sudo mkfs.xfs -f -L kimi-nvme /dev/md/kimi
sudo mkdir -p /mnt/kimi && sudo mount -o noatime LABEL=kimi-nvme /mnt/kimi
sudo chown "$USER":"$USER" /mnt/kimi
df -h /mnt/kimi

Success: df shows about 28T at /mnt/kimi. Do not add it to /etc/fstab with a hard mount. After deallocation the devices come back blank and boot would hang; the boot unit in Section 6 recreates it.

Host driver vs container CUDA. The container ships the CUDA runtime libraries; the host provides only the kernel driver and libcuda. A container works when the host driver is at least the minimum for the container's CUDA major/minor version. NVIDIA's release notes list R580 for CUDA 13.0 and ≥ 580 as the 13.x minor-version-compatibility floor; CUDA 12.9 needs ≥ 575.51.03 [DOC]. vLLM's default images are CUDA 13.0 per the v0.32.0 release notes; that v0.31.0 is also 13.0 is [EXP], and step 2.5 verifies it. If the container reports CUDA newer than 13.0, switch to v0.31.0-x86_64-cu129 rather than upgrading the host driver.

Version choice. vLLM v0.32.0 (2026-10-18) is two days old. v0.31.0 has been out for 16 days and is well above both the K2.5 recipe's verified v0.17.0 and the K2.6 recipe's ≥ 0.25.0 minimum. The recipe's v0.17.0 is the only version Moonshot/vLLM state as verified for K2.5 [DOC]; v0.31.0 with K2.5 is [EXP] until your smoke test passes. If it fails, v0.17.0 is the documented fallback.

3. Reproducible vLLM deployment

vLLM serves moonshotai/Kimi-K2.5 at a pinned commit from local NVMe. It runs in a digest-pinned container, listens only on 127.0.0.1:8000, and is managed by systemd. Every flag below comes from the vLLM K2.5 recipe or from the memory plan.

3.1 Pin and record the model revision and container digest — [VM]

3.2 Download the weights once — [VM]

The repository is not gated (gated: false, HF API), so no HF token is needed.

set -a; . /etc/kimi-pins.env; set +a
DEST=/mnt/kimi/models/Kimi-K2.5
mkdir -p "$DEST"
docker run --rm -v /mnt/kimi:/mnt/kimi --entrypoint hf "$VLLM_IMAGE" \
  download "$MODEL_REPO" --revision "$MODEL_REV" --local-dir "$DEST"
echo "$MODEL_REV" > "$DEST/.revision"

Verify against the hub's own sizes and LFS SHA-256s:

curl -fsS "https://huggingface.co/api/models/${MODEL_REPO}/tree/${MODEL_REV}?recursive=1" > ~/kimi/tree.json
jq -r '.[] | select(.type=="file") | "\(.path)\t\(.size)\t\(.lfs.oid // "-")"' ~/kimi/tree.json > ~/kimi/manifest.tsv
wc -l ~/kimi/manifest.tsv; ls "$DEST"/*.safetensors | wc -l          # expect 64 shards
fail=0; while IFS=$'\t' read -r p s oid; do
  a=$(stat -c %s "$DEST/$p" 2>/dev/null || echo MISSING); [ "$a" = "$s" ] || { echo "SIZE $p $a != $s"; fail=1; }
done < ~/kimi/manifest.tsv; echo "size check fail=$fail"
# SHA-256 of LFS files (several minutes; parallel)
awk -F'\t' '$3!="-"{print $3"  "$1}' ~/kimi/manifest.tsv > ~/kimi/lfs.sha256
(cd "$DEST" && sha256sum --quiet -c ~/kimi/lfs.sha256) && echo "SHA OK"

Success: size check fail=0, 64 shards, SHA OK. Total is about 595 GB. Failure: a mismatched file gets deleted and re-downloaded with the same hf download command, which resumes. If the tree API rate-limits you, wait and retry. Do not skip verification.

4. Secure remote access

Pick one option. A puts nginx with a Let's Encrypt certificate on the VM and opens only TCP 443 (and 80 for ACME). B opens no inbound port and reaches the VM through a named Cloudflare Tunnel guarded by Cloudflare Access. In both, port 8000 is bound to loopback and never appears in the NSG, only two API routes are reachable, and /health, /metrics, /invocations, /tokenize, /pause and the other routes vLLM leaves unauthenticated (vLLM security doc) return 404.

Recommendation: Option B if you will use the browser front end (Open WebUI) on your phone. Option A if you want a native OpenAI-compatible app, because few apps can send Cloudflare's extra headers (Section 5).

Option B — named Cloudflare Tunnel with Access

Tunnel is transport; Access is authorisation. cloudflared makes outbound-only connections from the VM to Cloudflare, so no inbound port is needed. That alone authenticates nobody. Cloudflare Access policies decide who may reach each hostname, and cloudflared checks Access's signed JWT (Cf-Access-Jwt-Assertion) before forwarding, through originRequest.access (origin parameters). vLLM's own bearer key is a third, independent layer.

Prerequisites: a Cloudflare account; a domain whose DNS zone is active on Cloudflare (nameservers moved) so cloudflared tunnel route dns can create the hostnames; and a Zero Trust organisation, which gives you the <TEAM> name in <TEAM>.cloudflareaccess.com.

B.6 Two separate authentication headers. An API client must send both:

6.6 On-VM idle shutdown with draining — [VM]

GPU utilisation is not a valid idle signal: it is about 0% between a user's messages, and non-zero during CUDA-graph capture at startup. The watcher uses vLLM's own request counters instead.

sudo tee /usr/local/sbin/kimi-idle.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
# Deallocates this VM after IDLE_MIN of no inference activity, with grace and draining.
set -uo pipefail
IDLE_MIN=20; BOOT_GRACE_MIN=60; STATE=/var/lib/kimi/idle.state
m(){ curl -fsS --max-time 5 http://127.0.0.1:8000/metrics 2>/dev/null | awk -v k="$1" '$1 ~ "^"k"({|$)" {s+=$2} END{printf "%d", s+0}'; }
up_min=$(( $(cut -d. -f1 /proc/uptime) / 60 ))
[ "$up_min" -lt "$BOOT_GRACE_MIN" ] && exit 0                                  # boot, restore and load grace
[ "$(systemctl show -p ActiveState --value kimi-restore)" = activating ] && exit 0  # weights still restoring
[ -n "$(who)" ] && exit 0                                                       # an admin is logged in
[ -f /var/lib/kimi/keep-awake ] && exit 0                                       # manual override
run=$(m vllm:num_requests_running); wait=$(m vllm:num_requests_waiting); tok=$(m vllm:prompt_tokens_total)
now=$(date +%s); read -r last_tok last_t < "$STATE" 2>/dev/null || { last_tok=-1; last_t=$now; }
if [ "$run" -gt 0 ] || [ "$wait" -gt 0 ] || [ "$tok" != "$last_tok" ]; then echo "$tok $now" > "$STATE"; exit 0; fi
[ $(( (now - last_t) / 60 )) -lt "$IDLE_MIN" ] && exit 0
logger -t kimi-idle "idle ${IDLE_MIN}m: draining"
systemctl stop nginx cloudflared 2>/dev/null                                   # stop new requests at the edge
for i in $(seq 1 24); do [ "$(m vllm:num_requests_running)" -eq 0 ] && [ "$(m vllm:num_requests_waiting)" -eq 0 ] && break; sleep 5; done
systemctl stop kimi-webui kimi-vllm
RID=$(curl -fsS -H Metadata:true "http://169.254.169.254/metadata/instance/compute/resourceId?api-version=2021-02-01&format=text")
TOK=$(curl -fsS -H Metadata:true "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https%3A%2F%2Fmanagement.azure.com%2F" | jq -r .access_token)
logger -t kimi-idle "deallocating $RID"
curl -fsS -X POST -H "Authorization: Bearer $TOK" -H 'Content-Length: 0' "https://management.azure.com${RID}/deallocate?api-version=2024-07-01"
EOF
sudo chmod 0750 /usr/local/sbin/kimi-idle.sh
printf '[Unit]\nDescription=Kimi idle check\n[Service]\nType=oneshot\nExecStart=/usr/local/sbin/kimi-idle.sh\n' | sudo tee /etc/systemd/system/kimi-idle.service
printf '[Unit]\nDescription=Kimi idle check every 5 min\n[Timer]\nOnBootSec=10min\nOnUnitActiveSec=5min\n[Install]\nWantedBy=timers.target\n' | sudo tee /etc/systemd/system/kimi-idle.timer
sudo systemctl daemon-reload && sudo systemctl enable --now kimi-idle.timer
curl -s http://127.0.0.1:8000/metrics | grep -E '^vllm:(num_requests_running|num_requests_waiting|prompt_tokens_total)' | head

The last command verifies the metric names exist in your vLLM build [EXP]. If they differ, fix them in the script, or the watcher will treat a busy server as idle. Test: set IDLE_MIN=1 and BOOT_GRACE_MIN=0, leave the VM idle, and watch journalctl -t kimi-idle. Pass: "draining" then "deallocating", and 6.3 then reads PowerState/deallocated. Repeat while streaming a long answer; pass if no deallocation occurs until the answer completes and 20 minutes pass.

6.7 Restart and cache restoration — [VM]

After every deallocation, the NVMe RAID and the weights are gone. This unit rebuilds them before kimi-vllm starts.

sudo cp ~/kimi/manifest.tsv /etc/kimi-manifest.tsv
sudo tee /usr/local/sbin/kimi-restore.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
. /etc/kimi-pins.env
log(){ logger -t kimi-restore "$*"; echo "$(date -u +%T) $*"; }
log start
if ! findmnt /mnt/kimi >/dev/null; then
  mdadm --assemble --scan || true
  if [ -e /dev/md/kimi ]; then mount -o noatime /dev/md/kimi /mnt/kimi
  else
    CAND=$(lsblk -dn -o NAME,TYPE,MODEL | awk '$2=="disk" && /NVMe Direct/ {print "/dev/"$1}')
    for d in $CAND; do [ "$(lsblk -n "$d" | wc -l)" -eq 1 ] && [ -z "$(wipefs -n "$d")" ] || { log "refusing: $d not blank"; exit 1; }; done
    mdadm --create /dev/md/kimi --level=0 --raid-devices=$(echo $CAND | wc -w) $CAND --force --run
    mkfs.xfs -f -L kimi-nvme /dev/md/kimi; mkdir -p /mnt/kimi; mount -o noatime /dev/md/kimi /mnt/kimi
  fi
fi
D=/mnt/kimi/models/Kimi-K2.5
if [ "$(cat $D/.revision 2>/dev/null)" != "$MODEL_REV" ]; then
  log "azcopy restore $MODEL_REV"; mkdir -p "$D"
  AZCOPY_AUTO_LOGIN_TYPE=MSI azcopy copy "https://${SA}.blob.core.windows.net/models/Kimi-K2.5/${MODEL_REV}/*" "$D/" --recursive --log-level ERROR
fi
bad=0; while IFS=$'\t' read -r p s _; do [ "$(stat -c %s "$D/$p" 2>/dev/null)" = "$s" ] || { log "size mismatch $p"; bad=1; }; done < /etc/kimi-manifest.tsv
[ $bad -eq 0 ] || exit 1
log done
EOF
sudo chmod 0750 /usr/local/sbin/kimi-restore.sh
printf '[Unit]\nDescription=Restore NVMe RAID and Kimi weights\nAfter=network-online.target\nWants=network-online.target\n[Service]\nType=oneshot\nRemainAfterExit=yes\nTimeoutStartSec=3h\nExecStart=/usr/local/sbin/kimi-restore.sh\n[Install]\nWantedBy=multi-user.target\n' | sudo tee /etc/systemd/system/kimi-restore.service
sudo systemctl daemon-reload && sudo systemctl enable kimi-restore kimi-vllm kimi-webui
