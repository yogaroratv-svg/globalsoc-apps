3,307 Requests for Files That Should Never Be on a Web Server

One request in three to our PHP honeypot was not an exploit at all. It was a plain GET for a file that holds credentials: .env, .git/config, AWS keys, database dumps. Here are the 882 paths they asked for, who asked, and the AndroxGh0st check that came with them.

Part of the PHP honeypot series. Data: nginx request log from vm-php-cve-lab, 22 October – 15 November 2026 (UTC; the VM was switched off from 9 to 15 November). Every request on this page is shown as it was logged.

1. Summary

The largest single category of traffic to the honeypot needed no vulnerability. Between 2026-10-22 and 2026-11-09, 114 source IPs sent 3,307 requests for 884 different paths, each one a file that would hand over credentials if it existed: application environment files, Git metadata, cloud provider key files, database dumps, editor and CI configuration.

That is one third of all external requests the honeypot logged. Responses: 404 x 3,279, 200 x 16, 403 x 11, 400 x 1. Nothing was leaked, because the honeypot's web root contains one file. Section 8 covers the 16 requests that got a 200.

These requests are worth studying because the path list is the attacker's model of how developers make mistakes. Every path below is on the list because it has paid off somewhere.

3. .env in 479 Places

A .env file holds an application's settings as KEY=value lines: database password, mail server login, payment and cloud API keys, the framework's signing key. Laravel, Symfony, Node, Django and Rails projects all use one. It belongs one level above the web root. When the project root is the web root, /.env is a public URL.

Reading it top to bottom:

  • GET /tqzjwpy3sm89ne is a calibration request. A random path that cannot exist shows the scanner what this server's "not found" looks like, so a site that answers 200 to everything does not flood it with false hits.
  • GET /../.env tries to step out of the web root. nginx answered 400.
  • /?phpinfo=-1 and /app_dev.php/_profiler/open?file=app/config/parameters.yml are not file guesses. The first triggers a debug page in some PHP applications; the second is the Symfony profiler's file viewer, which reads any project file when the development front controller is left on a production host.
  • /sendgrid.env, /twilio.env, /aws.env: service-specific names. A key for a mail or SMS provider is directly saleable for spam.
  • /claude.env, /.claude/.env, /bedrock.env, /.bedrock/.env: new entries. Keys for AI model APIs are billed by usage and resold. There is a separate post on the AI-related probing this honeypot saw.

7. AndroxGh0st: the POST That Travels With /.env

255 requests in the log were not GETs. From 2026-10-24 00:58:33 to 2026-11-09 02:33:46 UTC, 7 IPs sent a form POST to / with one of two bodies:

 253  0x%5B%5D=androxgh0st
   2  0x01%5B%5D=legion

URL-decoded, that is 0x[]=androxgh0st: an array parameter named 0x with a single value. The first pair we received:

2026-10-24 00:58:32 UTC  78.153.140.149 (United Kingdom)  status 404  request 242 bytes  response 485 bytes
GET /.env HTTP/1.1
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/116.0.5845.140 Safari/537.36

2026-10-24 00:58:33 UTC  78.153.140.149 (United Kingdom)  status 200  request 328 bytes  response 1941 bytes
POST / HTTP/1.1
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/116.0.5845.140 Safari/537.36
Content-Type: application/x-www-form-urlencoded

0x%5B%5D=androxgh0st

This pattern is the published signature of the AndroxGh0st malware (CISA/FBI advisory AA24-016A, January 2024). It is a Python tool that harvests Laravel .env files and then uses what it finds: SMTP logins and SendGrid/Twilio keys for spam, AWS keys to create users and instances. The scanner works in two steps:

  1. GET /.env. If the file is served, parse it.
  2. POST / with 0x[]=androxgh0st. A Laravel application with APP_DEBUG=true responds to an unexpected POST with its debug error page, and that page prints every environment variable. The tool searches the response for APP_KEY, DB_PASSWORD, MAIL_PASSWORD, AWS_ACCESS_KEY_ID and similar names. The parameter value is only a marker.

With a leaked APP_KEY the same toolset can forge an encrypted Laravel cookie carrying a serialised object (CVE-2018-15133) and get code execution. The request that would do that never came here, because step 1 and step 2 found nothing.

legion in place of androxgh0st is the marker of the Legion credential harvester, a related tool sold on Telegram with the same technique.

The response to every one of these POSTs: 200 x 255 (1941 bytes). That is the compressed size of the honeypot's ordinary home page, which contains none of the strings the tool looks for.

8. Did Anything Leak?

No. 16 requests in this category were answered 200:

   3  GET /?phpinfo=-1 HTTP/1.1  (3689 bytes)
   3  GET /?url=.env HTTP/1.1  (3689 bytes)
   2  GET /index.php/info.php HTTP/1.1  (1941 bytes)
   2  GET /index.php/.env.example HTTP/1.1  (1941 bytes)
   2  GET /index.php/.env HTTP/1.1  (1941 bytes)
   2  GET /index.php/phpinfo.php HTTP/1.1  (1941 bytes)
   2  GET /index.php/phpinfo HTTP/1.1  (1941 bytes)

All of them are the home page. /?phpinfo=-1 and /?url=.env are / with a query string the page ignores. /index.php/.env is index.php with extra path information: Apache runs the script and passes /.env to it as PATH_INFO. 3,689 bytes is the page uncompressed and 1,941 is the same page gzipped.

A scanner that judges by status code alone would have recorded all 16 as hits. This is why the better tools send the calibration request shown in section 6, and why a 200 count in your own logs needs the response size beside it.

The eleven 403 responses are Apache's built-in rule that denies any file starting with .ht, plus mod_status refusing a non-local client:

   5  GET /.htaccess HTTP/1.1
   5  GET /.htpasswd HTTP/1.1
   1  GET /server-status HTTP/1.1

A 403 tells the scanner the server is Apache and that the path is special. A 404 tells it nothing.

9. Packet Capture Note

The lab ran a rolling packet capture (tcpdump, full snap length, 20 files of 10 MB) on port 80 and the Docker bridges. A ring that small holds about a day and a half of traffic, and the last of it was overwritten on 15 November when the VM was restarted and a large package download passed through the capture filter. The packets for the requests in this post no longer exist. What remains is the nginx request log (request line, User-Agent, Content-Type and the complete request body) and the Apache log from inside the container, both shipped to Microsoft Sentinel as they were written. Every payload on this page is from those two sources.

For this category the capture would add little. These are header-only GET requests, and the nginx log has the request line, User-Agent, status and sizes for all 3,307 of them. The one thing nginx did not log is the request headers other than User-Agent.

11. Detection (KQL)

Secret-file requests by source, with the two numbers that matter: how many were not refused, and how large the answers were.

Syslog
| where TimeGenerated > ago(7d)
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| extend Client = tostring(j.client), Uri = tolower(tostring(j.uri)), Status = toint(j.status), BytesOut = tolong(j.bytes_out)
| where Uri matches regex @"(\.env|/\.git|/\.svn|/\.aws|/\.ssh|id_rsa|wp-config\.|credentials|\.sql$|\.bak$|docker-compose|\.npmrc|tfstate|sftp.*\.json)"
| summarize Requests = count(), Paths = dcount(Uri), Served = countif(Status == 200), MaxBytes = max(BytesOut), SamplePaths = make_set(Uri, 5) by Client
| order by Served desc, Requests desc

On a production site, alert on Served > 0, then confirm by size. AndroxGh0st and Legion by body:

Syslog
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| where tostring(j.method) == "POST" and tostring(j.body) matches regex @"^0x[0-9a-f]*(%5B%5D|\[\])=(androxgh0st|legion)"
| summarize Posts = count(), Days = dcount(bin(TimeGenerated, 1d)), First = min(TimeGenerated), Last = max(TimeGenerated) by Client = tostring(j.client)

Most access logs do not record POST bodies. Without the body, the same actor shows as GET /.env followed within a second or two by POST / from the same IP.

12. Mitigation

  • Serve a sub-directory, not the project. The web root should be public/ (Laravel, Symfony) or a build output folder. Then .env, .git, vendor/ and storage/ have no URL at all. This one change removes most of this page.
  • Deny dotfiles at the web server as a second layer. nginx: location ~ /\.(?!well-known) { return 404; }. Apache: RedirectMatch 404 "/\.(?!well-known)". Return 404, not 403.
  • Deploy artefacts, not checkouts. git archive, a CI build, or a container image without .git. Add .git and .env* to .dockerignore.
  • Never edit or back up in place. cp wp-config.php wp-config.php.bak inside the web root publishes the database password. Editors do this silently (~, .swp, .save).
  • APP_DEBUG=false in production. It is the whole of AndroxGh0st's second step.
  • Test yourself. From outside: curl -s -o /dev/null -w '%{http_code} %{size_download}\n' https://your-site/.env, and the same for /.git/config and /.env.bak. Anything other than a 404 needs a look.
  • If one was exposed, rotate. Assume it was read. Change every credential in the file; check cloud audit logs for new users, keys and instances; check mail provider logs for sending you did not do.
