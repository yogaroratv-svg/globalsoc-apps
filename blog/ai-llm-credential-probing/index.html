The Newest Entries in the Scanner Wordlist: AI Keys, Coding-Agent Tokens and MCP Servers

A PHP honeypot with nothing to do with AI received 178 requests for Claude, OpenAI, Bedrock and Gemini key files, coding-agent credential stores, and MCP server endpoints. The first arrived three and a half hours after the server went online. Here is every path and the one MCP handshake we captured.

Key Sections: Summary · Coding-Agent Credential Files · Model API Key Files · A Directory Census · MCP Endpoint Scanning · The MCP Handshake · Open Model APIs · Who Is Asking · Packet Capture Note · IOCs · Detection (KQL) · Mitigation

Part of the PHP honeypot series. Data: nginx request log from vm-php-cve-lab, 22 October – 15 November 2026 (UTC). Every request on this page is shown as it was logged.

1. Summary

The honeypot is an Apache/PHP server with one page. It runs no model, no agent and no MCP server, and nothing on it suggests otherwise. Between 2026-10-22 and 2026-11-15 it still received 178 requests from 73 IPs for 101 AI-related paths. All were answered 404.

GroupRequestsSource IPsDistinct paths
MCP server endpoints74654
Model API key files53448
AI coding-tool config and tokens45544
Model API endpoints424
llms.txt211

That is under 2% of the honeypot's traffic, far behind .env and .git (see the secrets post). It is here because of what it shows: the wordlists have been updated. The technique is the same as for /.env, a plain GET for a file that should not be reachable, pointed at a new kind of secret.

Why these secrets are wanted: a model API key is billed by usage, works from anywhere, and is resold as cheap access or used directly until the owner notices the invoice. A coding agent's token file is worse, because it carries the account's subscription and sometimes access to connected repositories and tools.

5. MCP Endpoint Scanning

The largest group by request count is not a file. The Model Context Protocol lets an AI client call tools on a remote server over HTTP. By convention the "Streamable HTTP" transport listens on /mcp and the older SSE transport on /sse. An MCP server reachable without authentication will list its tools to anyone, and will run them.

74 requests from 65 IPs:

These are bare GETs. A real MCP endpoint answers a GET on /sse with an event stream and a GET on /mcp with 405 or a stream, so the response code alone tells the scanner whether to look closer.

6. The MCP Handshake

One scanner went a step further and spoke the protocol:

2026-11-05 19:06:22 UTC  45.156.129.80 (Portugal)  status 404  request 513 bytes  response 485 bytes

POST /mcp HTTP/1.1
User-Agent: python-httpx/0.28.1
Content-Type: application/json

{"jsonrpc":"2.0","id":4205234,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{"sampling":{},"elicitation":{},"roots":{"listChanged":true}},"clientInfo":{"name":"internet-census-mcp-scanner","version":"1.0.0"}}}

Formatted:

{
  "jsonrpc": "2.0",
  "id": 4205234,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "sampling": {},
      "elicitation": {},
      "roots": {
        "listChanged": true
      }
    },
    "clientInfo": {
      "name": "internet-census-mcp-scanner",
      "version": "1.0.0"
    }
  }
}
FieldMeaning
"jsonrpc": "2.0", "id"MCP messages are JSON-RPC 2.0. The id ties the reply to the request.
"method": "initialize"The mandatory first message of every MCP session. The client states what it supports; the server replies with its own name, version and capabilities.
"protocolVersion": "2025-06-18"The MCP specification revision the client speaks.
"capabilities"What the client offers the server: sampling (the server may ask the client's model to generate text), elicitation (the server may ask the user a question), roots (the client will tell the server which folders it may work in). Declaring all three makes the scanner look like a full-featured client.
"clientInfo"Self-identification: internet-census-mcp-scanner 1.0.0.

A live server would answer with serverInfo (product name and version) and its capability list. That reply is the whole point for a census: it fingerprints the software. The follow-up a hostile client would send is tools/list, then tools/call.

Everything this address sent:

2026-11-05 19:06:22  POST /mcp HTTP/1.1  -> 404
2026-11-05 19:06:23  GET /sse HTTP/1.1  -> 404
2026-11-05 19:06:23  GET /favicon.ico HTTP/1.1  -> 404

The source, 45.156.129.80, is in the same address block as the probes that requested /bitsight/internet_census/probe in the PHP2Shell data, and the client name matches. This looks like a security-ratings census, not an attack. It still shows what the opening move against an exposed MCP server is, byte for byte.

7. Open Model APIs

21:02:12  GET /v1/models HTTP/1.1  -> 404
21:02:26  GET /v1/embeddings HTTP/1.1  -> 404
21:02:44  GET /v1/completions HTTP/1.1  -> 404

164.52.24.185, 31 October. /v1/models is the model-listing call of the OpenAI API, which self-hosted inference servers (vLLM, LiteLLM, LM Studio, Ollama's compatibility layer and others) copy so that existing clients work. Many are started without an API key on a port someone later exposes. A 200 with a JSON model list means free inference on someone else's GPU, or a proxy that forwards to a paid provider with the owner's key. /v1/embeddings and /v1/completions check which calls are enabled.

Two requests for /llms.txt came from a crawler that also fetched robots.txt, sitemap.xml and security.txt. That file is a proposed convention for describing a site to language models. It is a content crawler and is counted here only for completeness.

9. Packet Capture Note

The lab ran a rolling packet capture (tcpdump, full snap length, 20 files of 10 MB) on port 80 and the Docker bridges. A ring that small holds about a day and a half of traffic, and the last of it was overwritten on 15 November when the VM was restarted and a large package download passed through the capture filter. The packets for the requests in this post no longer exist. What remains is the nginx request log (request line, User-Agent, Content-Type and the complete request body) and the Apache log from inside the container, both shipped to Microsoft Sentinel as they were written. Every payload on this page is from those two sources.

Everything in this post is in the nginx log in full: these are short GETs and one 240-byte JSON POST whose body was logged complete.

11. Detection (KQL)

Syslog
| where TimeGenerated > ago(7d)
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| extend Client = tostring(j.client), Uri = tolower(tostring(j.uri)), UA = tostring(j.user_agent), Status = toint(j.status), Body = tostring(j.body)
| extend Kind = case(
    Uri matches regex @"^/(api/)?mcp/?$|^/sse$", "MCP endpoint",
    Uri matches regex @"^/\.(claude|codex|cursor|gemini|aider|windsurf|amazonq|junie|opencode|kilocode|roo|qwen|continue|kiro|trae|augment)", "Coding-agent folder",
    Uri matches regex @"mcp[_.-]?(config|settings)?\.(json|ya?ml)|claude_desktop_config", "MCP client config",
    Uri matches regex @"(openai|anthropic|claude|bedrock|gemini|huggingface)", "Model API key file",
    Uri matches regex @"^/v1/(models|completions|chat/completions|embeddings)", "Model API",
    "")
| where isnotempty(Kind)
| summarize Requests = count(), IPs = dcount(Client), Served = countif(Status !in (404, 400)), Sample = make_set(Uri, 6) by Kind, UA
| order by Served desc, Requests desc

Grouping by User-Agent instead of client IP is deliberate; it is what makes the distributed MCP scan in section 5 show up as one row. As elsewhere in this series, Served > 0 is the alert.

An MCP handshake from an unknown client:

Syslog
| where SyslogMessage startswith "php_http: "
| extend j = parse_json(substring(SyslogMessage, 10))
| where tostring(j.method) == "POST" and tostring(j.body) has "\"jsonrpc\"" and tostring(j.body) has "\"initialize\""
| extend ClientName = tostring(parse_json(tostring(j.body)).params.clientInfo.name)
| project TimeGenerated, Client = tostring(j.client), Uri = tostring(j.uri), ClientName, Status = toint(j.status)

12. Mitigation

  • Never serve a home directory or a working project folder. Every path in sections 2 to 4 depends on that mistake. If you must share a file, serve a new empty directory containing only that file.
  • Deny dotfiles at the web server (location ~ /\.(?!well-known) { return 404; }) and keep .claude/, .cursor/, .codex/, .mcp.json and similar out of images and deploy bundles with .dockerignore and your CI's exclude list. Decide deliberately which of them belong in Git.
  • Keep secrets out of MCP config files. Reference an environment variable or a secret manager instead of pasting a token into an env block that lives in the project.
  • MCP servers: bind to 127.0.0.1 unless remote access is the purpose. If it is, require authentication (the specification defines OAuth for HTTP transports) and put the server behind a gateway. Treat every tool as callable by whoever can reach the port.
  • Self-hosted model APIs: set an API key, bind to localhost or a private network, and check from outside with curl http://your-host:port/v1/models.
  • Limit the damage of a leaked key. Per-project keys with spend limits, usage alerts, and provider-side restrictions where offered. For Bedrock, a dedicated IAM principal that can invoke models and nothing else.
  • If a credential file was reachable, rotate. Revoke the agent's login (log out all sessions at the provider), rotate every key in the file, and review the provider's usage log for the exposure window.
